## Arch Linuxを入れようとしたら、家にあるUSBメモリが古かった

前回、Arch Linuxを本格的に使ってみることにした。秋葉原で中古のDell Latitude 7420を買って、こいつをArch Linux専用機にする。

では、さっそくインストールに必要になるのが、Arch LinuxのISOイメージを書き込むためのUSBメモリである。
USBメモリくらい、家のどこかにあるだろうと思って、探してみた。

### 1. 256MBという名の遺物

最初に出てきたのは、BUFFALOの「ClipDrive mini」シリーズ、**256MB**。
256GBではない。256MBである。

調べてみると、RUF2-Mシリーズはすでに販売終了となっているモデルで、販売当時（2006年くらい）としてはごく当たり前の容量だったのだろう。しかし今見ると、なかなかのインパクトがある。Arch LinuxのISOを書き込むには、容量が足りない。当然、現在のインストール用としては全く使えない。

気を取り直して、もう一本発掘した。

### 2. 16GB、だがしかし

今度出てきたのは、HIDISCの「HDUF127S16G2」。容量は16GBだ。
これならArch Linuxのインストールメディアとして十分な容量がある。メーカーの仕様を確認しても、USB 2.0（USB 1.1互換）、Type-A、スライド式と、普通に使う分には何の問題もない。

わざわざ新しいものを買わなくても、これで事足りる。
……そう、事足りるはずだった。ただ一つ、気になってしまったのだ。
**USB 2.0か……。**

### 3. ということで、せっかくなので新しいUSBメモリを買う

これからLinuxをいじいじするにあたって、ISOを書き換えたり、ライブUSBを作ったり、気分次第で別のディストリビューションを試したりすることもあるだろう。それなら、インストール用として一本くらい、まともな仕様のUSBメモリを持っておいてもバチは当たまい。

そう自分を納得させ、新しく買ってきたのがこれだ。

* **製品名：** ADATA UV128 64GB（AUV128-64G-RBE-I）
* **仕様：** 64GB / USB Type-A / USB 3.2 Gen 1（スライド式）
* **公称値：** 最大読み出し 100MB/s

アドデータ公式データシートでもビックカメラの商品ページでも、USB 3.2 Gen 1（USB 5Gbps）対応として掲載されている。

## USB 2.0とUSB 3.xは何が違うのか

さらにUSBについて調べていると、面白い話を見つけた。

**USB 3.xのType-A機器をゆっくり挿すと、USB 2.0として認識されることがあるらしい**

そんな馬鹿な、と思ったが、しかし、これはエレコムやDellの公式情報でも言及されている、USB 3.x Type-Aの構造に由来するれっきとした挙動らしい。
なぜそんなことが起こるのか。

### Type-Aコネクタの物理的な構造

普段よく見るUSB Type-Aについて、

* **USB 2.0**で使うのは、基本となる4つの接点（VBUS、D-、D+、GND）。
* **USB 3.0**では高速なSuperSpeed通信を実現するため、これだけでは足りず、さらに5つの接点が追加されて**合計9接点**になる。

そのため、USBメモリは、端子の部分を目視することで、どの世代の者なのかということが大体わかる。

> 色で見分けることもできなくはないが、企画できちんと定まっていないため、メーカーごとに違ったり、詐称されてたりする。てかそもそも、USB 3.0の名称をころころ変えたこともそうだが、USB Implementers Forumはいったい何をしているのか...

重要なのはその配置だ。USB 2.0との後方互換性を維持するため、従来の4接点をそのまま手前側に残し、その**奥側**にSuperSpeed用の追加接点が並んでいる。

```text
[ USB Type-A 端子のイメージ ]

入口 ───────────────────────────── 奥
 [ USB 2.0用接点 ]   [ SuperSpeed用接点 ]

```

### 「ゆっくり挿す」と何が起きるのか

普通にUSBメモリをカチッと奥まで挿し込めば、両方の接点がほぼ同時に接続され、USB 3.xとしてのリンクが確立する。

ところが、極端にゆっくり挿していくと、

1. まず手前にある**USB 2.0側の接点だけ**が接触した状態が作られる。
2. PC側は「USBデバイスが接続された」と判断し、手前の接点だけで認識処理を進めてしまう。
3. その結果、**USB 3.x対応機器であるにもかかわらず、USB 2.0（High-Speed）として動作してしまう**。

一度この状態で認識されてしまうと、そのあと奥まで押し込んでも自動でUSB 3.xへ切り替わってはくれない。一度抜いて、一続きの動作でしっかり奥まで挿し直す必要がある。

### 480Mbpsと5Gbps


* USB 2.0 High-Speed：最大 **480 Mbps**
* USB 3.2 Gen 1：最大 **5000 Mbps**（約10.4倍）

性能差は、約１０倍で、かなり違いが出る。もちろん前述の通り、USBメモリ側のフラッシュ性能（100MB/s）がボトルネックになる場面もある。

## Linuxなら接続速度も見える

せっかくLinux環境を作るのだから、この手の挙動もあとで実際に自分の手で確認してみたい。
Linuxであれば、ターミナルで次のようなコマンドを叩くだけでその実態がわかる。

* `lsusb -t`
USBデバイスが現在どのバス速度で接続されているかを確認できる。USB 2.0なら `480M`、USB 3.xなら `5000M` のように表示される。
* `dmesg -w`
カーネルのログをリアルタイムで監視しながらUSB機器を抜き差しすれば、OSがデバイスをどう認識していくかをライブで見られる。

WindowsでUSBメモリを挿したときは「USBメモリが使えるようになった」で完結していたことが、Linuxでは「今、カーネルからこのハードウェアはどう見えているのか」というレイヤーまで確認できる。Arch Linuxを使おうと思った最初の動機と、ここで綺麗につながってきた気がする。

#### 「5Gbps」と「100MB/s」は何が違うのか

少し気になって調べてみた。
USB 3.2 Gen 1の公称信号速度は5Gbpsである。これを単純にbitからbyteへ換算してみる。

$$5 \text{ Gbit/s} \div 8 = 625 \text{ MB/s}$$

では、このUSBメモリも625MB/sで読み書きできるのかといえば、答えは残念ながらNoだ。ADATAの公式スペックがうたう最大読み出し速度は**100MB/s**にとどまる。

なぜこれほどの乖離が生まれるのか。
要するに、**「USB 3.2 Gen 1」という規格が示しているのは、あくまで通信路側の最大速度**であって、USBメモリ内部のNANDフラッシュやコントローラがその速度に対応していることを保証するわけではないからだ。

構造をざっくり図式化するとこうなる。

```text
[ PC ]
  │
  │ USB 3.2 Gen 1 （最大5Gbpsの通信路）
  ▼
[ USBコントローラ ]
  │
  ▼
[ NANDフラッシュメモリ ] （実際のストレージ性能：最大100MB/s）

```

道路の制限速度がどれだけ速くても、車自体の性能が追いついていなければ意味がない。さらに、実際の通信にはプロトコル上のオーバーヘッドも乗っかってくる。つまり、「規格上の転送速度」と「ストレージ自体の実効性能」は別物として考える必要があるわけだ。
