> これは本文レイアウトと記事追加フローを確認するための架空の技術メモです。

## 最初に決めた境界

ページの中心は静的なHTMLにして、操作が必要な場所だけへ小さなスクリプトを足す構成を想定しました。記事本文はスクリプトが読み込めない環境でも、そのまま読める状態を保ちます。

設計時に比べた観点は次の3つです。

1. 記事をファイル単位で追加できること
2. 一覧と詳細でメタデータの正本を共有できること
3. 表示に不要なJavaScriptを配信しないこと

## データと本文を分ける

一覧で使うタイトルや日付は型付きデータに置き、長い本文はMarkdownへ置きます。本文ファイルは安定したIDでメタデータを参照します。

```ts
interface EntryFrontmatter {
  readonly sourceId: string;
}
```

この境界なら、タイトル変更で本文ファイルとの関係が壊れません。逆に本文が欠けた場合は、ビルド中にエラーとして検出できます。

## 確認表

| 確認対象 | 期待する結果 |
| --- | --- |
| JavaScript無効 | 本文とリンクを読める |
| 狭い画面 | コードと表だけ横方向へ確認できる |
| 見出し | 目次から該当箇所へ移動できる |

詳しい仕様は[Astroの公式ドキュメント](https://docs.astro.build/)でも確認できます（外部サイト）。
