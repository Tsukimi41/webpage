# デザイン・モーション方針

最終更新: 2026-09-14  
状態: 基本方針は決定、具体的な書体・配色・モチーフは未決定

## 1. デザイン目標

### 決定事項

- 暗色を基調としつつ、緑のアクセントで見ていて楽しい印象を作る
- 現代的で整然としている
- 技術感を持たせる
- 親しみやすく、過度に企業的・無機質にしない
- 黒、緑、灰色を基調とした暗色テーマを基本とする
- 角丸は控えめにし、四角に近い形を基本とする
- CSSアニメーションを中心に視覚的な仕掛けを設ける
- 長文の記事ページでは可読性を優先する
- 書体をブランド表現の一部として扱う
- 無料で利用でき、Webサイトへの埋め込み条件が明確なフォントを使用する

## 2. 参考サイトから取り入れる設計判断

### [堀元見のブログ](https://ken-horimoto.com/)

参考にする点:

- キャラクターや問いかけによって、運営者の人格を感じる導線を作っている
- メニュー、検索、プロフィール、活動実績がブログと同じ世界観で統合されている
- 記事タイトルと概要が強く、一覧だけでも内容への興味を作る

そのまま採用しない点:

- 同じキャラクター表現や文体の模倣
- 就職向けの情報到達を遅らせる大きな演出

### [@771-8bit](https://771-8bit.com/)

参考にする点:

- 記事タイトル、投稿日・更新日、読了時間、概要の明快な一覧
- タグ、検索、アーカイブによる記事資産へのアクセス
- 制作・実験・備忘録が一つのブログに自然に蓄積されている

### [ぎがおにおん](https://gigaonion.com/)

参考にする点:

- サイトを見た瞬間に伝わる強いコンセプト
- 制作者の技術的な興味とサイトの表現が一致している
- ポートフォリオ自体を技術作品として見せている

そのまま採用しない点:

- 黒と緑のターミナル表現そのもの
- 長文記事まで同じ高コントラストな演出で統一すること

### [SHINNの研究室](https://shinn-chan.net/)

参考にする点:

- プロフィール、活動履歴、スキルが順に理解できる情報設計

- 外部リンクへ迷わず移動できる構成

## 3. 視覚コンセプト

### 暫定コンセプト: 「暗いデジタル工作室」

- 黒に近い緑がかった背景を基調にする
- 明るい緑を主要アクセントとし、文字と境界には白寄りの灰色を使う
- 面の階層は濃度の異なる灰色で表現し、色数を増やしすぎない
- カードや操作要素の角丸は数px程度に抑え、四角に近い形を使う
- グリッド、ドット、コード、回路・接続線を想起させる抽象的な要素で技術感を出す
- 装飾よりも、制作物の画像、技術名、成果、文章を主役にする
- ポートフォリオ部分は楽しく、記事本文は落ち着いて読みやすくする

## 4. ページごとのデザイン密度

### ホーム・プロフィール

- 色と動きを比較的多く使う
- 人柄、注力技術、代表作品を短時間で印象付ける
- 最初の画面内に自己紹介と代表的な実績への導線を置く

### プロジェクト

- 作品画像、成果、担当範囲を優先する
- カードは装飾ではなく、情報のまとまりとして使う
- 技術タグは色だけで分類せず、文字ラベルを併記する

### タイムライン

- 年、出来事、説明の階層を明確にする
- 縦線と節点を基本形とする
- スクロール時に線・節点が段階的に現れる演出を候補とする
- アニメーションが無効でも、最初から完全な年表を読めるようにする

### ブログ記事

- 背景と本文のコントラストを優先する
- 本文幅を長文が読みやすい範囲に制限する
- 見出し、リンク、引用、コード、表の見分けを明確にする
- 記事本文で常時動く装飾は原則使わない

## 5. タイポグラフィ

### 5.1 原則（決定）

- 無料フォントを使用する
- 現代的で整然とした印象を基本にする
- 技術感を出しつつ、親しみやすくポップにする
- 日本語フォントを主軸に選定する
- フォントファイルを必要に応じてサイト側から配信し、端末依存の差を抑える
- 日本語フォントは最大2ファミリー、コード用は最大1ファミリーを目安とする
- 使用ウェイトを絞り、表示速度を優先する

### 5.2 候補（暫定）

第一候補:

- 見出し: `M PLUS Rounded 1c`
- 本文: `Noto Sans JP`
- コード・英数字のアクセント: `JetBrains Mono`

比較候補:

- `Zen Kaku Gothic New`: 現代的で整った本文・見出し
- `Zen Maru Gothic`: やわらかいアクセント
- `M PLUS 1 Code`: コード・技術的な英数字表現

最終決定では、ライセンス、可読性、必要な字形、ファイル容量、Safariでの描画を確認する。

### 5.3 基本サイズ（暫定）

- 本文: 1rem以上
- 通常ラベル・ナビゲーション: 原則0.875rem以上
- 注釈・補助情報: 原則0.75rem以上
- 本文行間: 1.7前後を基準に書体ごとに調整
- ブラウザの文字サイズ変更と200%拡大を妨げない

## 6. モーション設計

### 6.1 原則（決定）

- 動きは「楽しさ」「情報の階層」「操作への反応」のいずれかに役割を持たせる
- CSS Transition / CSS Animationを中心とする
- スクロール開始判定など、CSSだけでは扱いにくい箇所に限って小さなJavaScriptを使う
- `transform` と `opacity` を優先する
- `transition: all` は避け、変化するプロパティを指定する
- 動きがなくても情報や操作が失われない構造にする
- 低性能端末でも読み進められることを優先する

### 6.2 採用候補

| 場所 | 動き | 目的 | 状態 |
| --- | --- | --- | --- |
| ファーストビュー | 文字・小さな図形の段階的登場 | 第一印象と楽しさ | 暫定 |
| 得意領域 | キーワードの短い切り替え | 技術領域を素早く伝える | 未決定 |
| プロジェクトカード | 浮き上がり、影・色の変化 | 操作可能性を伝える | 暫定 |
| タイムライン | 線が伸び、節点が現れる | 時間の流れを表現する | 暫定 |
| セクション見出し | 小さなスライド＋フェード | 読むリズムを作る | 暫定 |
| ボタン | 短い縮小・復元 | 操作への反応 | 暫定 |
| ヒーロー背景 | ゆっくりした限定的な色・形の変化 | ポップな世界観 | 未決定 |
| キャラクター・モチーフ | 状態に応じた小さな反応 | 人格と記憶性 | 未決定 |

### 6.3 使用しない演出（暫定）

- コンテンツ表示を待たせる長いイントロ
- 常時大きく動く背景
- 強い点滅やストロボ表現
- 読み終える前に切り替わる長文タイプライター
- 実際の待ち時間がないローディングスピナー
- マウスホバー時にだけ重要情報を表示する仕組み
- ページ内のすべての要素に同じ登場アニメーションを付けること

### 6.4 アクセシビリティ

- `@media (prefers-reduced-motion: reduce)` で大きな移動、拡大、回転、バウンドを無効化または短いフェードへ置換する
- 初回表示ではページ全体を短くフェードインし、主要情報を小さな時間差で表示する
- 5秒を超えて自動継続する動きは原則使用しない。必要な場合は一時停止または停止操作を設ける
- 動きの停止操作を設ける場合は、キーボードで操作でき、名前とフォーカス表示を持たせる
- 同一ページ内で多数の無限ループを動かさない

## 7. レスポンシブ方針

### 決定事項

- モバイルファーストで設計する
- iPhone、Android、PCで情報内容と操作手段を欠落させない
- ホバーは補助表現とし、操作の必須条件にしない
- タップ対象は十分な大きさと間隔を確保する
- 横幅320px程度でも意図しない横スクロールを発生させない

### 暫定レイアウト

- スマートフォン: 1カラム
- タブレット: 内容に応じて1〜2カラム
- PC: プロジェクト等は2〜3カラム、記事本文は読みやすい固定上限幅
- タイムライン: モバイルでは片側配置、広い画面では交互配置も比較検討する

## 8. クロスブラウザ方針

- 標準化され、対象ブラウザで安定したCSSを基礎にする
- 新しいCSS機能を使う場合は、`@supports` などで段階的に強化する
- Safariだけ未対応の機能に主要レイアウトや操作を依存させない
- CSSリセット、共通デザイントークン、明示的な行高・余白で差異を抑える
- Webフォントの読み込み失敗時には、近いメトリクスのフォールバックを指定する
- 実装後に対象ブラウザと代表画面幅で確認する

- ダークモードの有無
- タイムラインのPC表示を片側配置または交互配置のどちらにするか

- 写真、アバター、プロジェクト画像の方針
