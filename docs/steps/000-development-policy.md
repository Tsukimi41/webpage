# Step 000: 開発方針をGitで追跡する

- 目的: 合意した要件・設計・開発ルールを、今後の実装と照合できるリポジトリ内の基準として残す。
- 対象ユーザー: サイトを開発・確認する本人。
- 今回作るもの: `docs/` 配下の設計文書をGitで追跡できる状態と、このステップの記録。
- 今回作らないもの: サイト本体、フレームワーク設定、パッケージ管理設定、画面、コンテンツ、デザイン。
- 受入条件:
  - `docs/` 配下の設計文書が `.gitignore` の対象になっていない。
  - 要件、デザイン、技術・運用、開発フローの文書がGitの変更対象として確認できる。
  - サイト本体の実装ファイルを追加していない。
  - 秘密情報や公開しない個人情報を追加していない。
- 関連する既存機能: Gitリポジトリと既存の設計文書。
- 将来の拡張候補: Step 001以降で、小規模プロトタイプを使って技術構成を検証する。

## 実装・確認結果

- `.gitignore` から `docs/*` を削除した。
- `git status --short` で `.gitignore` の変更と `docs/` の追加候補を確認した。
- `git check-ignore` で6文書が無視されていないことを確認した。
- サイト本体の実装ファイルは追加していない。
- 秘密情報を示す代表的な文字列を検索し、実値の混入がないことを確認した。検索で見つかったのは、公開禁止事項として記載した「学籍番号」の説明だけだった。
