# Step 001: Astro候補を検証する最小基盤

- 目的: 静的なポートフォリオ兼ブログの基盤として、Astroが最小構成でビルドできることを確認する。
- 対象ユーザー: サイトを開発・更新する本人。
- 今回作るもの:
  - AstroとTypeScriptの最小構成
  - `/` で表示できる、内容を持たない基盤確認用トップページ
  - 開発・ビルド・プレビュー用のnpmスクリプト
  - 生成物とローカル設定を除外するGit設定
- 今回作らないもの:
  - Astroとnpmの正式採用
  - 自己紹介、所属、プロジェクト、タイムライン、記事などの実コンテンツ
  - デザイントークン、Webフォント、アニメーション、画像
  - 複数ページ、MDX、コンテンツコレクション、外部連携
  - 公開・デプロイ
- 受入条件:
  - `npm run build` が警告・エラーなく成功する。
  - `/` が静的HTMLとして生成される。
  - 生成されたHTMLにページタイトル、言語指定、viewport指定、`main` ランドマーク、見出しがある。
  - クライアント側JavaScriptを追加していない。
  - 320px幅でも横スクロールを生む固定幅を使用していない。
  - 秘密情報や公開しない個人情報を含まない。
- 関連する既存機能: ADR-001（静的サイト）、ADR-003（Astroを第一候補）、段階的開発方針。
- 将来の拡張候補: 次のステップで最小デザイントークンを追加し、その後に自己紹介領域を実データで作る。

## 実装・確認結果

- Astro 7.3.2、TypeScript strict設定、npmスクリプトを最小構成で追加した。
- `/` 用のトップページを追加し、実コンテンツとデザインは後続ステップへ分離した。
- `npm install` は成功し、既知の脆弱性は0件だった。
- `npm run build` は警告・エラーなく成功し、`dist/index.html` を静的生成した。
- ローカル開発サーバーの `/` がHTTP 200を返すことを確認した。
- 生成HTMLに日本語指定、viewport、固有タイトル、`main`、`h1` があることを確認した。
- 生成物にscript要素とJavaScriptファイルがないことを確認した。
- ソースに固定ピクセル幅と秘密情報を示す代表的な文字列がないことを確認した。
- `git diff --check` で空白エラーがないことを確認した。
- 既存の未コミット変更 `docs/development-workflow.md` は、このステップの変更対象に含めず保持した。
